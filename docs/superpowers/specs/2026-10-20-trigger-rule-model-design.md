# Design: 触发规则模型（编辑投影 + 原生保真）

**日期:** 2026-10-20  
**状态:** 待用户确认  
**范围:** v1 — 规则列表编辑体验；原生 plist 保真往返；预设识别；自定义/异常日历兜底  
**关系:** 承接并收紧 [2026-10-16-multi-trigger-support-design.md](./2026-10-16-multi-trigger-support-design.md)。多触发并存、多日历、多 WatchPaths 仍成立；用「规则投影 + 变更集写回」替换「扁平字段 + Toggle + 每隔 N 月展开」。

## 背景

10-16 多触发落地后，表单仍以「定时 / 间隔 / 监视」Toggle + 混杂日历字段组织，并把「每隔 N 月」错误地展开为固定 `Month` 集合。这既不符合 launchd「缺字段=通配、无跨年周期计数器」的语义，也无法在打开→保存时保证不改写既有配置。

用户需要：规则列表式编辑、日/周/月/年预设清晰、多监视路径、且**尽可能还原 launchd**——保留原生表达能力、避免错误的周期承诺、无修改往返不变语义。

## 目标

| 能力 | v1 |
|------|-----|
| 规则列表编辑（多规则并存） | ✅ |
| 每日 / 每周（星期多选）/ 每月（可选月份）/ 每年预设 | ✅ |
| 时间间隔（`StartInterval`，最多 1 条） | ✅ |
| 监视路径（可多条） | ✅ |
| 自定义日历：预设无法表达时可见并原样保留 | ✅ |
| 配置异常（类型/范围非法）可见且不静默改写 | ✅ |
| 未支持键（如 `QueueDirectories`）可见且往返保留 | ✅ |
| 无修改不重写文件；有修改时变更集更新 | ✅ |
| 任意「每隔 N 月」周期展开 | ❌ |
| 一次性任务 / 截止重复（需 App 辅助） | ❌ |
| 完整自定义日历字段编辑器 | ❌（v1 摘要 + 保留；完整编辑可走 XML） |

## 总约束

> **原始 plist 文档负责保真，NativeTriggers 负责解析，TriggerRule 负责展示和编辑；保存以变更集更新原始文档，不从整个规则列表重建全部配置。**

## 方案选择

| 决策 | 选择 | 理由 |
|------|------|------|
| 架构 | 两层：原生配置 + 编辑投影 | 编译多对一；无法从 plist 唯一还原 UI 意图 |
| 每月 | 指定日+时刻，可限定月份（每年重复） | launchd 无跨年「每隔 N 月」计数器 |
| 月份快捷 | 全部 / 多选 / 每季度 / 每半年 | UX 便利；写出仍是带 Month 的条目集合 |
| 往返承诺 | 保留值、类型与结构；不发明字段 | `raw` 已是解析对象，不承诺字节级 XML 不变 |
| 根文档 | 保留整个原始 plist 根对象 | 避免为「缺键 vs 空数组」「单 dict vs 单元素 array」另造状态 |
| WatchPaths | 表单可多条 | 与 launchd 数组一致 |
| RunAtLoad | 留在选项区；文案「加载任务时运行一次」 | 对应 job load，非打开 App / 非仅开机 |

## 架构

### 三层职责

| 层 | 职责 |
|----|------|
| **原始 plist 文档** | 打开时的根对象快照；保存时只替换实际修改的键或条目 |
| **NativeTriggers（解析）** | 从根对象读出日历条目、`StartInterval`、`WatchPaths`、passthrough；附带解析诊断 |
| **TriggerRule（投影）** | 预设 / 自定义 / 异常的展示与编辑；带 `sourceRefs`；会话内稳定 ID |

App 元数据（规则 ID、合并展示偏好、间隔单位）可另存；**若磁盘 plist 相对编辑开始快照有变化，丢弃元数据覆盖、重新解析。** 打开时与**保存前**均须检测外部修改。

### 原生解析视图

```text
NativeTriggers
  calendarEntries: [CalendarEntry]
  startInterval: Int?                 // 便捷；与诊断一起解释「缺键 / 有值 / 非法」
  watchPaths: [String]
  // 诊断与形态（由根文档 + 解析得出，不单独伪造持久状态）：
  // - StartCalendarInterval: 缺键 | 空 array | 单 dict | array
  // - WatchPaths: 缺键 | 空 array | 非空
```

```text
CalendarEntry
  // 便捷字段（Int? = 缺键或未解析出有效 Int；不能单独表示「键在但非法」）
  weekday / month / day / hour / minute: Int?
  raw: [String: Any]                  // 该条目的原始字典
  diagnostics: [ParseIssue]           // 未知子键、错误类型、越界等
```

**Optional 说明：** `Int?` 只有两态。第三种情况（键存在但类型错误/越界）由 `raw` + `diagnostics` 表达。预设识别要求：**键集合精确匹配，且所有值的 plist 类型与范围均合法。**

合法范围（与 launchd 常见约定一致，写入预设时遵守）：

| 键 | 合法 |
|----|------|
| Minute | 0…59 |
| Hour | 0…23 |
| Day | 1…31 |
| Month | 1…12 |
| Weekday | 0…7（0 与 7 均表示周日；未编辑时保留原值） |

`Hour: "9"` / `true` / `99` 等：不识别为预设，归入**配置异常**自定义（与「有效但无预设」区分展示）。

### 编辑投影 `TriggerRule`

```text
TriggerRule
  id: UUID                            // 会话 / 可选元数据；不写入 plist
  kind: daily | weekly | monthly | yearly | interval | watchPath | customCalendar
  // kind 对应编辑字段…
  sourceRefs: [SourceRef]             // 对应的原生 entry / path 标识（会话内）
  isModified: Bool
```

```text
SourceRef
  kind: calendarEntry | watchPath | startInterval
  sessionId: UUID                     // 打开文档时分配；会话内稳定
  // 禁止仅靠可变数组下标或仅靠内容匹配（允许重复条目）
```

**写入所有权（互斥）**

| 键 | 模块 |
|----|------|
| `StartCalendarInterval`, `StartInterval`, `WatchPaths` | 触发器模块 |
| `RunAtLoad`, `KeepAlive` | 选项模块 |
| 其余键 | 原始文档保留（passthrough） |

同一键不得由两个模块同时输出。

**条目写回状态机**

> 未修改条目使用 `raw`；修改条目使用编辑结果；禁止同时改 `raw` 与投影字段。

- 未修改的合并规则：原位置、原内容保留（不重排整个日历数组）。  
- 修改合并规则：只替换其 `sourceRefs` 指向的条目。  
- 增加星期/月份：新条目按固定策略插入（见下）。  
- 删除合并规则：删除引用的全部条目；UI 标明「删除整组」。  
- 新建或**新产生**的日历键：可统一输出 array；**未修改**时保留原来的单 dict / array 形态。  
- 整个文档相对打开快照无修改：不重写文件。

**新条目插入策略（v1 固定）**

- 扩展合并周规则的新 Weekday dict：紧接该组合并组中最后一条 `sourceRef` 之后插入。  
- 扩展月份同理。  
- 全新规则：追加到 `StartCalendarInterval` 数组末尾（若原为单 dict，先升级为 array 再追加——仅当该键因本次编辑被触碰时）。

### 预设识别表

按**完整字段集合**精确匹配，且值类型与范围合法：

| 恰好出现的键 | 识别 |
|--------------|------|
| `Hour`, `Minute` | 每日 |
| `Weekday`, `Hour`, `Minute` | 每周（同时刻多条可合并展示） |
| `Day`, `Hour`, `Minute` | 每月 · 全部月份 |
| `Month`, `Day`, `Hour`, `Minute` | 见月份展示约定 |
| 其它合法组合（如仅 `Minute`） | 自定义日历（有效） |
| 非法类型/越界/未知子键导致无法安全当预设 | 自定义日历（配置异常） |
| `Day` + `Weekday` 同条 | 自定义；预设永不生成该组合 |

**月份展示约定（非用户意图证明）**

- 多条仅 `Month` 不同、其余键与值相同且均通过校验 → 合并展示为「每月 · 指定月份」。  
- 单条带 `Month` → 展示「每年」。  
- 不因合并静默去重。  
- 即使聚齐 12 个月，也**不**删除 `Month` 改写成一条无 Month 的每月规则。  
- 元数据失效后：**展示类型可能变，原生配置不变。**

**每周合并展示**

- 同时刻、仅 Weekday 不同的合法条目可合并为一行「周一至周五 …」等。  
- 投影必须带齐 A/C 的 `sourceRefs`（见示例：A 周一 09:00、B 每日 18:00、C 周二 09:00 → A+C 合并，B 独立）。  
- 文案用「周一至周五」，不用「工作日」（不暗示法定节假日）。

## 表单 UX

### 结构

1. 列表顶部说明（固定文案）：  
   **「以下触发规则独立生效，任一规则触发时均可启动任务。」**  
   补充（帮助或次要行）：顺序仅用于展示，无优先级；不承诺每次触发一次独立执行、排队、补跑或并发语义。
2. 规则列表：每行一种投影（预设 / 自定义 / 异常 / 间隔 / 监视）。
3. 「+ 添加规则」→ 选类型 → 填字段。
4. 自定义（有效）：显示字段摘要（如 `Minute=15`）；v1 只读或「在 XML 中编辑」。
5. 自定义（异常）：标「配置异常」+ 简短原因；保留 raw；不提供「一键修复」静默改值。
6. Passthrough 触发相关键：只读列表「其它启动条件」，保存时保留。

### 各类型编辑器

| 类型 | 控件 |
|------|------|
| 每日 | 时、分（均必填；写出含 Hour+Minute） |
| 每周 | 星期多选 + 时、分 |
| 每月 | 日 + 时、分；月份：全部 / 多选 / 快捷每季度、每半年 |
| 每年 | 月、日、时、分 |
| 时间间隔 | 数量 + 单位（秒/分/时/天）；最多一条；选「天」时副文案「每 24 小时（86400 秒）」 |
| 监视路径 | 路径字符串；可多条；路径当前不存在可提示，不视为配置无效 |

### 帮助文案（节选）

- **时间间隔：** 休眠或任务仍在运行时可能错过该次触发；与日历互不重置，不是「距任意规则上次启动后 N 秒」。  
- **日历：** 休眠期间错过的触发可能在唤醒时合并处理；关机期间错过的不承诺开机补跑。  
- **WatchPaths：** 可能遗漏事件；触发不代表文件已写入完成。不提供未实现的「递归监视」「写完再触发」「每次变化恰好一次」。  
- **RunAtLoad：** 「加载任务时运行一次」。若保存会 unload/load，提示可能立即运行。选项区同时展示 KeepAlive 等，避免误以为「只在规则列表的时间运行」。

### 列表 / 主界面摘要

- 按投影行展示（合并周/月显示为一行）。  
- 自定义与异常有区分标记。  
- Passthrough 条件以次要行或「+N 其它条件」提示。  
- `runAtLoad`：加载时运行一次。  
- 皆无：无自动触发。

## 错误处理与冲突

| 情况 | 行为 |
|------|------|
| 日历 array 中非法元素 | 保留为异常自定义；不丢条目 |
| 外部在编辑期间改文件 | 保存前检测；重新加载或冲突提示；禁止用旧 raw 覆盖 |
| 再添加第二条间隔 | UI 禁用或替换确认 |
| 每月 31 日 / 2 月 29 日 | 原样保存；不自动改成月末或其它日 |
| 删除合并周规则 | 确认删除整组（全部 sourceRefs） |

## 测试 / 验收

- **无修改往返：** 导入后直接保存（或保存时检测无变更）→ **不重写文件**。有变更时仅用变更集更新；未改条目不补默认值、不做隐式规范化。  
- **局部修改：** 只改一条规则，不影响其它日历条目、WatchPaths、passthrough。  
- **形态保留：** 未触碰时保留单 dict vs array、缺键 vs 空数组。  
- **预设边界：** 缺 `Minute` 的 `{Hour:9}` 不识别为每日、不补 Minute=0。  
- **月份：** 不把「1,6,11」当成任意每隔 5 月；12 个月聚合不剥 Month。  
- **合并映射：** A/C 合并编辑只写回 A/C；B 不动。  
- **Day+Weekday：** 导入为自定义；预设 UI 不生成。  
- **原生语义（手工）：** 目标 macOS 上抽查休眠、任务运行中、时区/DST；间隔与日历独立评估。

## 模块变更概览

```
LaunchManager/
├── Models/
│   ├── LaunchItem.swift          # 列表摘要改为基于投影；编辑态持有根文档快照
│   ├── NativeTriggers.swift      # 解析视图 + CalendarEntry + diagnostics
│   └── TriggerRule.swift         # 投影 + sourceRefs + kinds
├── Services/
│   ├── PlistService.swift        # 根文档加载；变更集写回；外部修改检测
│   └── TriggerCompiler.swift     # 识别预设 / 编译编辑结果（纯函数，易测）
├── Views/
│   ├── EditAgentSheet.swift      # 规则列表替换 Toggle 区
│   └── AgentRowView.swift        # 摘要行对齐投影
└── LaunchManagerTests/
    └── LaunchManagerTests.swift  # 往返、合并映射、非法值、形态保留
```

实现计划阶段再拆任务；本 spec 不绑定 `LaunchItem` 是否仍缓存 `calendarIntervals` 便捷字段（若保留，必须由原生文档派生，不得反向当真相）。

## 非目标

- App 辅助的一次性 / 截止时间  
- 任意 N 的「每隔 N 月」  
- 用元数据覆盖外部已改的 plist  
- WatchPaths 递归 / 写完触发等未实现语义  
- 表单完整编辑 `QueueDirectories` / `StartOnMount` / `Sockets`（仅保留）  
- 承诺关机补跑或「每次触发=一次执行」

## 修订记录（相对早期摘要）

| 原表述 | 修订 |
|--------|------|
| 每隔 N 月 → 展开 Month | 指定月份；快捷季度/半年 |
| 反编译还原 UI | 保留原生 + 识别预设；UI 意图靠元数据且可失效 |
| 字节级语义不变 | 保留值、类型与结构；无修改不重写文件 |
| Optional 三态 | 两态 + raw/diagnostics |
| 单 WatchPath | 可多条 |
| 合并仅展示 | 必须 `sourceRefs`；写回不重排无关条目 |
